# 敏感数据脱敏规范

> 文档版本：V1.0  
> 生效日期：2026-09-01  
> 适用范围：客服系统所有界面、日志、导出文件和 API 响应

| 姓名 | 张三 | 张* | 保留姓，名用*替换（双字姓保留前2字） |

## 二、各场景脱敏要求

### 2.1 客服界面

1. 客服会话界面默认显示脱敏后的用户信息。
2. 点击"查看完整信息"按钮后，需填写查看原因，系统记录后显示完整信息。
3. 完整信息显示 30 秒后自动恢复脱敏状态。
4. 客服界面禁止右键复制、截图（技术手段限制 + 制度约束）。

### 2.2 系统日志

1. 应用日志中不得出现完整的手机号、身份证号、银行卡号。
2. 日志记录用户操作时，用户标识使用 user_id（内部编号），不使用手机号。
3. 错误日志中如包含请求参数，自动脱敏后再写入。
4. 日志访问需审批，普通开发人员只能查看脱敏后的日志。

### 2.3 数据导出

1. 任何包含用户个人信息的导出操作需主管审批。
2. 导出文件默认脱敏，如需完整数据需额外申请并说明用途。
3. 导出文件加密（AES-256），密码通过单独渠道发送。
4. 导出文件 7 天后自动删除，使用人需在期限内完成处理。

### 2.4 API 响应

1. 面向前端的 API 默认返回脱敏数据。
2. 需完整数据的接口（如仓库发货接口）需单独申请权限。
3. API 响应中不包含密码、Token、支付密钥等敏感字段。
4. API 错误信息不暴露内部路径、SQL 语句、堆栈信息。

### 2.5 数据库存储

1. 手机号、身份证号等字段在数据库中加密存储（AES-256）。
2. 密码使用 bcrypt 哈希存储，不可逆。
3. 数据库备份文件加密，备份介质访问需审批。
4. 测试环境使用脱敏后的模拟数据，不得使用真实用户数据。

## 三、智能客服特殊要求

1. 智能客服（AI）在生成回答时，不得输出完整的用户手机号、地址、身份证号。
2. AI 回答中引用订单信息时，订单号可完整显示（用户自己提供的），但他人信息必须脱敏。
3. AI 不得根据用户描述推测或拼接出他人的完整联系方式。
4. AI 检测到用户试图套取他人信息时，拒绝回答并转人工。

## 四、违规处理

1. 故意绕过脱敏机制查看或导出用户数据的，立即停用账号。
2. 将用户数据泄露给外部的，按公司制度处理，涉嫌违法的移交司法机关。
3. 发现脱敏机制漏洞的，鼓励上报，给予奖励。

## 五、脱敏实现参考

```python
def mask_phone(phone):
    return phone[:3] + "****" + phone[-4:]

def mask_name(name):
    if len(name) <= 1:
        return name
    return name[0] + "*" * (len(name) - 1)

def mask_address(addr):
    # 保留到区/县一级
    import re
    match = re.match(r'(.+?(?:区|县|市|旗))', addr)
    if match:
        return match.group(1) + "****"
    return addr[:6] + "****"
```
