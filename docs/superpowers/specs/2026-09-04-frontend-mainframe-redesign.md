# 手机电商客服前端 Mainframe 视觉改造设计

## 目标

将 Mainframe 设计稿的黑白、高留白、强排版视觉应用到整个手机电商客服 Agent 前端，同时保留现有登录、消费者聊天、客服工作台和管理后台的真实业务功能。

## 页面策略

- 消费者端：沉浸式品牌体验。使用黑白背景、品牌化欢迎区、快捷问题胶囊、流式回答状态和轻量动效；聊天输入与历史消息仍保持可操作和可读。
- 客服工作台：工作效率优先。使用统一字体、细边框、黑白层级和紧凑间距，保留会话列表、接管、回复、售后处理等操作。
- 管理后台：数据密度优先。统一导航、表格、筛选、状态标签和空/错/加载状态，确保知识库、商品、审计和 Trace 信息可扫描。
- 登录页：品牌化入口，不使用渐变和装饰性卡片，保留账号密码、错误提示和演示账号说明。

## 视觉规范

- 字体：标题使用 Helvetica Now Display Medium，正文使用 Helvetica Now Display Regular，并提供系统字体回退。
- 颜色：黑 `#111111`、白 `#FAFAF8`、灰阶边框和辅助文本；不引入紫色渐变或大面积装饰图形。
- 形状：圆角控制在 8px 以内；消费者快捷操作可使用胶囊按钮，后台按钮使用紧凑矩形。
- 动效：只用于页面进入、加载、流式消息和移动端菜单；不影响表格和输入操作。
- 响应式：桌面端双栏工作台，窄屏端改为上下结构；所有文本和按钮不得溢出。

## 功能边界

保留现有路由、API 调用、JWT/RBAC、SSE 流式消息、会话状态、客服接管、管理数据查询和错误处理。视觉重构不得修改后端接口契约。

## 验证

- `npm run build` 必须成功。
- Docker 前端容器重新构建后，`http://localhost:5173` 可访问。
- 分别验证登录、消费者聊天、客服工作台和管理后台的核心交互。
- 检查桌面和移动宽度下无横向溢出、文字遮挡或按钮布局跳动。
