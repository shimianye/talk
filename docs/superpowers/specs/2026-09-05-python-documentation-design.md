# Python 核心代码注释设计

## 目标

为手机电商客服 Agent 的核心 Python 代码补全中文结构化注释，使开发者和面试官无需反复追踪实现即可理解每个函数的职责、输入输出、异常边界以及关键业务数据含义。此次工作只改善可读性，不改变任何运行行为或接口契约。

## 范围

包含以下代码：

- `backend/app`：FastAPI 路由、Agent 编排、LLM、RAG、安全、工具、服务、数据库与 ORM 模型。
- `backend/scripts/init_db.py`：数据库初始化、种子数据转换、校验和导入。
- `backend/alembic`：迁移环境和初始迁移函数。

不包含测试代码、`scripts/seedgen` 一次性数据生成脚本、第三方依赖、前端代码和生成产物。

## 注释规范

### 函数与方法

每个自定义函数和方法必须有中文 docstring。首句直接说明业务职责；存在参数、返回值或显式异常时，按实际需要使用：

- `Args`：说明参数的业务含义，不重复类型标注。
- `Returns`：说明返回数据的结构、关键字段和成功/失败语义。
- `Raises`：仅记录调用方需要处理的显式异常。

属性、抽象方法和极短的内部闭包也必须有职责说明，但不强制添加没有信息增量的空 `Args` 或 `Returns` 段落。

### 类与数据结构

为缺少说明的类补全中文 docstring。对以下关键结构补充字段级含义：

- `AgentState` 中的消息、意图、实体、工具调用、确认、转人工和 Trace 字段。
- `ToolContext`、`ToolResult`、`Tool` 中的用户身份、权限、执行结果和参数 Schema。
- `LLMResponse`、`ToolCall` 中的文本、工具调用、结束原因和 token 用量。
- ORM 模型中业务含义不直观的 ID、状态、金额、库存、权限和时间字段。

### 就近行注释

只在下列位置使用行注释：

- Agent 分支与循环终止条件。
- SQL 查询的权限隔离、商品 SPU/SKU 映射和促销生效规则。
- RAG 排名融合、向量回退和分块重叠逻辑。
- PII 脱敏、写操作确认、熔断与重试。
- Excel 字段到 ORM 字段的转换规则。

不写逐行语法翻译，不重复变量名或代码已经清楚表达的行为。

## 一致性要求

- 使用中文说明，技术名词保留常见英文缩写，如 LLM、RAG、SSE、JWT、SPU、SKU。
- 注释必须与当前实现一致，不描述尚未实现的能力。
- 不在注释中写入 API Key、密码或其他敏感值。
- 不借注释任务进行业务重构、格式化全仓库或修改公开接口。

## 验证

1. 使用 AST 扫描目标范围，确认每个自定义函数和方法都有 docstring。
2. 执行 `python -m compileall -q backend/app backend/scripts backend/alembic`。
3. 在 API 容器内执行 `pytest -q`，确认现有行为没有回归。
4. 检查 Git diff，确保改动仅包含注释、docstring 和必要的格式调整。
