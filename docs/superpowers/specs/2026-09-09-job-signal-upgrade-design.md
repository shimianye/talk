# 手机电商智能客服 Agent：求职证据增强设计

## 1. 背景与问题

项目已有完整的 Agent 图、工具权限、人工确认、审计、RAG、测试、CI、压测和演示视频，工程覆盖面足够。当前影响 AI 应用岗位求职说服力的主要问题不是功能数量，而是三条证据链没有闭合：

1. README 只有 Mock LLM 指标，无法回答“真实模型到底表现怎样”。
2. 用户只能看到答案，看不到经过脱敏后的意图、工具、来源和安全决策，Agent 的价值藏在代码里。
3. 管理端把评测结果显示成原始键值表，招聘方无法快速理解系统质量、失败边界和改进方向。

## 2. 目标

- 用一轮有上限、可追溯的真实模型小样本评测补齐真实效果证据。
- 在消费者端展示安全、简洁的决策摘要，让工具调用、引用和安全边界可见。
- 把管理端评测结果改成指标卡、口径说明和风险提示，而不是单纯列出 JSON 字段。
- 补充面试讲解材料，明确业务问题、技术取舍、失败案例和下一步。

成功标准：面试官在三分钟内能看懂项目解决什么问题、Agent 做了什么、如何防止误操作、真实效果如何、哪里仍不可靠。

## 3. 范围与非目标

### 本轮范围

- 后端聊天响应增加经过白名单过滤的 `decision_summary`。
- 聊天页增加可折叠的“本次 AI 决策依据”。
- 管理端评测页增加指标卡、中文口径和风险提示。
- 建立 24 条分层真实模型求职评测切片，并最多执行一轮真实评测。
- 更新 README，并新增面试讲解文档。

### 明确不做

- 不做云部署，不引入新的云账号和持续费用。
- 不把现有字符级 SSE 宣称为后端真流式，也不在本轮重构 LLM 流式接口。
- 不增加新的业务工具、数据库表或角色。
- 不为提高数字而改宽断言、改写样本期望或隐藏失败案例。

## 4. 架构与组件

### 4.1 决策摘要

在聊天服务完成 Agent 执行后，由独立的纯函数从最终状态生成摘要：

```text
decision_summary
├── trace_id
├── intent
├── actions[]       仅工具名称与成功状态
├── sources[]       仅可公开的标题/来源标识
├── safety_flags[]  仅前端允许展示的中文分类
├── handoff_required
└── mode            mock / deepseek
```

摘要采用白名单构造，不直接透传工具参数、工具结果、用户身份、订单号、手机号、原始 Trace 或内部 Prompt。没有信息时返回空数组，前端不猜测。

### 4.2 消费者端决策依据

每条 Agent 消息保留现有答案，并增加一个默认收起的详情区：

- “识别为：商品咨询 / 订单查询 / 售后申请”等中文意图。
- “调用：价格查询、知识库检索”等工具名称。
- “安全状态：正常 / 已脱敏 / 等待确认 / 转人工”。
- “来源”只显示后端明确提供的公开来源。

详情区不展示 Chain-of-Thought，只展示可审计事实。

### 4.3 管理端评测视图

评测接口保持兼容，前端在展示层完成以下转换：

- 第一行：意图准确率、工具选择准确率、转人工准确率、安全拦截率。
- 第二行：答案产出率、P50、P95、样本数。
- 每项显示中文口径和分母；缺失值显示“尚未评测”，绝不显示 0。
- 对低于约定阈值的指标显示“需要关注”，不使用“失败”制造误导。
- 明确区分 Mock 与真实模型，禁止混合比较。

### 4.4 真实模型评测切片

从现有 100 条数据中固定选择 24 条，覆盖商品参数、对比、推荐、价格、库存、订单、物流、售后、投诉、拒答、越权和转人工。样本 ID 固定并记录 SHA256，禁止根据结果临时换题。

执行规则：

- 只使用项目现有配置的 DeepSeek 模型和密钥，不新增供应商。
- 最多跑一轮 24 条，避免无上限外部调用；未配置密钥时不执行、不伪造数字。
- 报告记录 commit、模型、运行时间、数据集哈希、各指标分母和逐题失败原因。
- README 同时保留 Mock 基线与真实小样本结果，并明确两者不可直接横向比较。

## 5. 数据流

```text
用户消息
  → Agent 图与工具执行
  → 输出护栏与 Trace 持久化
  → 决策摘要白名单转换
  → Chat API / SSE message_start
  → 聊天答案 + 可折叠决策依据

管理员启动评测
  → 固定评测集运行
  → 指标与环境指纹
  → API 返回
  → 指标卡 + 口径 + 风险提示
```

## 6. 错误与安全处理

- 决策摘要生成失败不能影响主回答，降级为空摘要并记录服务端日志。
- 工具参数、工具结果、用户 ID、会话原文和内部 Prompt 永不进入摘要。
- SSE 失败继续使用现有同步降级；决策摘要跟随同步响应返回。
- 真实模型评测单题失败独立记录，整轮继续执行；不因异常重跑整轮。
- 页面只对后端提供的字段做展示，不从答案文本推断工具或安全状态。

## 7. 测试与验收

- 后端单测覆盖摘要白名单、空状态、脱敏、工具成功/失败、确认和转人工。
- 既有后端测试全部通过；数据库相关跳过项保持现有口径。
- 前端 TypeScript 构建通过。
- 手工验证聊天页的普通问答、工具调用、等待确认、转人工四种状态。
- 管理端在 Mock、真实模型未运行、真实模型已运行三种数据状态下均不误导。
- 若执行真实评测，报告必须能由命令重新生成，README 数字与报告一致。

## 8. 求职叙事

项目最终突出三个面试信号：

1. 我没有把 Agent 当作普通聊天框，而是把权限、确认、审计和人工接管放进执行路径。
2. 我不只展示成功案例，还用固定评测集区分 Mock 与真实模型，并保留失败样本。
3. 我不暴露模型思维过程，而是通过安全的决策摘要提升可解释性和可运营性。

## 9. 实施顺序

1. 后端决策摘要与测试。
2. 聊天页决策依据。
3. 管理端评测指标卡。
4. 固定真实评测切片并运行一次有上限的评测。
5. README、面试讲解文档、构建与回归验证。
