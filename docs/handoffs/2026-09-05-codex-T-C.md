## 完成内容

- 新增 `EVAL_DATABASE_URL`，要求评测库与主库位于同一 PostgreSQL 实例、使用同一账号、库名不同且以 `_eval` 结尾。
- 新增 `database_bootstrap` 服务：自动创建缺失的评测库，使用同一 Alembic 配置分别迁移主库和评测库，再在各自单一事务中同步业务种子和知识库。
- 新增 `scripts/bootstrap.py`，支持 `--database-url`、`--eval-database-url`、`--data-dir` 和 `--docs-dir` 显式覆盖。
- Compose 新增一次性 `init` 服务；API 只有在 `init` 成功退出后才启动。
- API 与 init 共用 embedding 和知识目录配置，避免两条初始化路径产生版本签名差异。
- 新增 URL 安全规则单元测试和真实 PostgreSQL 双库集成测试。

## 关键设计理由

- 评测库和主库共用一套 ORM、Alembic migration、种子同步与知识同步代码，避免评测环境形成旁路实现。
- 评测库以独立 database 隔离，防止评测过程污染演示或运行期业务数据。
- `CREATE DATABASE` 连接 PostgreSQL maintenance database 并使用 AUTOCOMMIT；数据库名先经过严格白名单校验。
- 双库无法组成跨 database 原子事务，因此每个库各自保证“种子 + 知识”单事务；失败时 init 非零退出，Compose 不启动 API。
