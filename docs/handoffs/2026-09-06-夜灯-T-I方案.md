## 核心难点

「体现打字机式渲染」本质是**时间维度**的动态过程,而 PNG 是单帧静态图。怎么用一张静图讲清「答案是一字一字蹦出来的」,是 T-I 的关键决策。

## 三个方案

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 单帧进行中 | 答案渲染到一半时截一张 | 最简单,单 PNG | 静图看不出「在动」,评审可能以为就是半句话 |
| B. GIF 动图 | 录屏 2-3 秒转 GIF | 真实展示打字机 | 不符合 PNG 规范,大 GIF 易超 1MB,README 引用的是 .png 路径 |
| **C. 多帧拼图(推荐)** | 在 3 个时刻各截一帧(答案刚出 / 渲染 1/3 / 渲染完成),横向拼成一张 PNG,标注时间 | 静态图能讲清「逐字增长」,符合 PNG 规范 | 需截 3 帧 + 拼接(夜灯可用脚本代拼) |

## 推荐:方案 C 多帧拼图

理由:一张图同时呈现「答案从短到长」的过程,无需动态媒体就能证明是流式渲染;且仍然符合 README 的 PNG 规范。夜灯可用 Python(PIL)把 3 帧横向拼接 + 加时间标注。

## 截图操作建议(失眠夜本机)

1. `docker compose up -d --build` 起服务,浏览器打开 `http://localhost:5173`,登录消费者 `U6147` / `password123`。
2. 选一个**会触发工具 + 较长回答**的问题(短回答打字机一闪而过截不到),例如:
   - 「对比 iPhone 16 Pro 和 iPhone 15 Pro 的处理器、价格,哪个更值得买」
   - 「iPhone 16 全系有哪些型号?各自什么配置」
3. 在答案**逐字渲染过程中**,按 3 个时间点各截一帧(建议间隔 ~0.5-1 秒):
   - 帧 1:答案刚出现(前几个字)
   - 帧 2:答案渲染到一半
   - 帧 3:答案完整
4. 3 帧 PNG 交给夜灯拼接(或自己用截图工具拼),输出替换 `02-consumer-chat.png`。
