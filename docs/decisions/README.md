# 技术决策文档（ADR）

> 本目录记录 phone-commerce-agent 在实现过程中做出的关键**技术决策**。
> 每一条决策回答三个问题：**为什么选它**、**放弃了什么**、**何时会失效**。

## 为什么要有这份文档

代码只能回答「怎么做的」，不能回答「为什么这么做、为什么没选别的」。
对招聘评审来说，后者更能体现工程判断力——尤其是「放弃的替代方案」和「失效条件」，
说明这不是拍脑袋选型，而是权衡过代价的。

## 决策记录的统一格式

每条决策（Decision）固定为四段：

```
## D-x <决策标题>
- 状态：已采纳 / 已采纳（待真实 LLM 验证）
- 背景：一句话说清要解决的问题
- 决策：为什么选它（附关键实现位置）
- 放弃的替代方案：曾经考虑过、最终没选的东西，以及放弃理由
- 失效条件：什么信号出现时，这个决策必须重新评估
```

## 状态标记含义

- **已采纳**：已在代码中落地并通过 CI（45 测试全绿）。
- **已采纳（待真实 LLM 验证）**：代码路径已就位、Mock 已跑通，
  但尚未用真实 DeepSeek/BGE-M3 端到端验证。这类决策在阶段二要重点回测。
